# Mini NPU Simulator

MAC(Multiply-Accumulate) 연산으로 입력 패턴이 어느 필터에 더 가까운지 판정하는 Python 콘솔 프로그램입니다.

## 실행 방법

```bash
python main.py
```

- 환경: Python 3.8 이상, 외부 라이브러리 없이 표준 라이브러리(`json`, `time`, `math`, `os`, `re`, `sys`)만 사용합니다.
- data.json 위치: `main.py`와 **같은 폴더**에 둡니다. (다른 폴더에서 실행해도 `main.py` 옆의 data.json을 읽습니다.)

실행하면 입력 방식을 선택합니다.

```
=== Mini NPU Simulator ===

[모드 선택]
1. 사용자 입력 (3x3)
2. data.json 분석
선택:
```

### 1. 사용자 입력 (3×3)
필터 A, 필터 B, 패턴을 차례로 3줄씩 입력합니다. 한 줄에 숫자 3개를 공백으로 구분해 입력합니다.
흐름: 필터 A, B 입력 → 저장 확인 → 패턴 입력 → MAC 연산 → 결과 판정(A / B / 판정 불가) → 성능 분석(3×3)

```
필터 A        필터 B        패턴
0 1 0         1 0 1         1 0 1
1 1 1         0 1 0         0 1 0
0 1 0         1 0 1         1 0 1
```
위와 같이 입력하면 `A 점수: 1.0`, `B 점수: 5.0`, 연산 시간, `판정: B`가 출력됩니다.

입력이 잘못되면 `입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요.`와 원인을 출력하고, 해당 행렬을 다시 입력받습니다.

| 잘못된 입력 | 원인 출력 |
|---|---|
| 빈 줄 | `행 수 불일치: 2번째 줄이 비어 있습니다 (3행 필요)` |
| 한 줄의 숫자가 3개가 아님 | `열 수 불일치: 2번째 줄의 숫자가 2개입니다 (3개 필요)` |
| 숫자가 아닌 값 | `숫자 파싱 실패: 2번째 줄 '1 a 1'` |

### 2. data.json 분석
흐름: 필터 로드 → 패턴 로드/검증 → MAC 연산·판정·PASS/FAIL 출력 → 성능 분석(3×3, 5×5, 13×13, 25×25) → 결과 요약

## 구현 요약

### 데이터 구조
`Matrix` 클래스가 n×n 값을 2차원 리스트로 저장합니다. `set(row, col, value)`로 특정 위치에 저장하고 `get(row, col)`로 읽습니다. 크기 제한이 없어 3×3, 5×5, 13×13, 25×25를 모두 처리합니다.

### 라벨 정규화
data.json에서는 같은 대상을 위치마다 다른 표기로 씁니다. 그대로 비교하면 `'+'`와 `'cross'`가 서로 다른 문자열이 되므로, 읽는 즉시 프로그램 내부 표준 라벨 `Cross`, `X`로 바꿉니다.

| 위치 | 입력 | 표준 라벨 |
|---|---|---|
| expected 값 | `'+'` | `Cross` |
| expected 값 | `'x'` | `X` |
| filter 키 | `'cross'` | `Cross` |
| filter 키 | `'x'` | `X` |

이 표에 없는 값은 해당 케이스(또는 필터)를 FAIL 처리하고 사유를 출력합니다. 콘솔 출력과 PASS/FAIL 비교는 표준 라벨로만 합니다.

### MAC 연산
MAC(Multiply-Accumulate)은 두 배열의 같은 위치 값을 곱하고(Multiply), 그 결과를 모두 더하는(Accumulate) 연산입니다. 결과 점수가 클수록 패턴이 그 필터와 비슷합니다. (명세 예시: 십자가 입력 × 십자가 필터 = 5, 십자가 입력 × X 필터 = 1)
AI 모델은 큰 필터를 많이 사용하므로 이미지 한 장에도 MAC 연산이 아주 많이 필요합니다. 그래서 MAC 속도가 AI 처리 속도를 좌우하고, MAC을 대량으로 동시에 처리하는 NPU가 쓰입니다.

이 프로그램은 NumPy 없이 2중 반복문으로 MAC을 구현했고, 점수(float)를 반환합니다.

```python
total = 0.0
for i in range(n):
    for j in range(n):
        total += pattern.get(i, j) * filt.get(i, j)
return total
```

### 동점 처리 정책 (epsilon)
`abs(score_a - score_b) < 1e-9`이면 동점으로 봅니다. 모드 1은 `판정 불가`, 모드 2는 `UNDECIDED`로 판정하고, 그 외에는 점수가 큰 쪽으로 판정합니다.
모드 2에서는 판정(Cross/X)이 expected와 같으면 PASS, 다르면 FAIL입니다. UNDECIDED는 expected와 같을 수 없으므로 FAIL입니다.

### 스키마·크기 검증 (모드 2)
패턴마다 아래를 검사합니다. 하나라도 실패하면 그 케이스만 FAIL로 처리하고 원인을 출력한 뒤 다음 케이스로 넘어갑니다. 프로그램은 중단되지 않습니다.

1. 키가 `size_{N}_{idx}` 형식인지 확인하고 N을 추출해 `size_N` 필터를 선택합니다.
2. 선택한 필터가 정상적으로 로드됐는지 확인합니다. (`cross`, `x`가 둘 다 있고 N×N이어야 합니다.)
3. 패턴 `input`과 필터의 크기가 일치하는지 확인합니다. (예: `크기 불일치: 패턴 13×13, 필터 5×5`)
4. `expected`가 정규화 규칙에 있는 값인지 확인합니다.

파일이 없거나 JSON 형식이 잘못된 경우에도 메시지를 출력하고 정상 종료합니다.

### 성능 측정 방식
- `time.perf_counter()`로 MAC 함수 호출 구간만 잽니다. (입력, 출력, 파일 읽기는 제외합니다.)
- MAC 연산마다 10회 반복하며 한 번씩 시간을 재고, 그 평균(ms)을 MAC 1회 시간으로 출력합니다. 출력 문구: `MAC 1회 평균, 필터별 10회 측정`
- 측정에 쓰는 데이터
  - 모드 1: 입력한 패턴과 필터 A, B (각 10회)
  - 모드 2의 3×3: 명세의 Case 1·Case 2 데이터 (십자가 입력과 십자가 필터, X 필터, 각 10회)
  - 모드 2의 5×5·13×13·25×25: data.json에서 해당 크기의 첫 패턴과 Cross 필터, X 필터 (각 10회)

## 결과 리포트

### 1. data.json 분석 결과

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---|---|---|---|---|
| size_5_1 | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL (동점 규칙) |
| size_5_2 | 8.9 | 0.1 | Cross | Cross | PASS |
| size_13_1 | 0.3 | 14.700000000000008 | X | X | PASS |
| size_13_2 | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL (동점 규칙) |
| size_25_1 | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL (동점 규칙) |
| size_25_2 | 52.9 | 0.1 | Cross | Cross | PASS |

총 테스트 6개, 통과 3개, 실패 3개입니다.

### 2. FAIL 원인 분석

실패 3건(size_5_1, size_13_2, size_25_1)의 원인을 "데이터/스키마 문제 → 로직 문제 → 수치 비교 문제" 순서로 확인했습니다.

**데이터/스키마 문제: 해당 없음.** 3건 모두 키에서 N이 정상 추출되었고, 패턴과 필터의 크기가 같습니다. expected(`'x'`, `'+'`)와 필터 키(`'cross'`, `'x'`)도 표준 라벨로 정규화되었습니다. 같은 크기의 다른 케이스(size_5_2, size_13_1, size_25_2)는 PASS입니다.

**로직 문제: 해당 없음.** data.json의 값으로 직접 계산한 결과와 프로그램 점수가 일치합니다. 3건 모두 수학적으로는 두 점수가 같습니다.

| 케이스 (입력 모양) | Cross 필터와 겹치는 칸 | X 필터와 겹치는 칸 |
|---|---|---|
| size_5_1 (X) | 가운데 1칸: 0.9 × 1 = 0.9 | 대각선 9칸: 0.1 × 9 = 0.9 |
| size_13_2 (십자가) | 십자 25칸: 0.3 × 25 = 7.5 | 가운데 1칸: 7.5 × 1 = 7.5 |
| size_25_1 (X) | 가운데 1칸: 4.9 × 1 = 4.9 | 대각선 49칸: 0.1 × 49 = 4.9 |

**수치 비교 문제: 원인.** 0.1과 0.3은 2진 부동소수점으로 정확히 표현되지 않습니다. 그래서 여러 번 더하면 아주 작은 오차가 생깁니다. (0.1을 9번 더하면 0.9가 아니라 0.8999999999999999)
3건의 점수 차이는 각각 1.11e-16, 2.66e-15, 1.78e-15로, 모두 1e-9보다 작습니다. 따라서 동점 정책에 따라 UNDECIDED가 되고, expected(X, Cross, X)와 다르므로 FAIL입니다. 명세의 결과 예시에서도 0.9 대 0.8999999999999999는 `UNDECIDED | FAIL (동점 규칙)`로 처리됩니다.

**epsilon 정책이 필요한 이유.** epsilon 없이 `>`로만 비교하면 3건은 각각 Cross, X, Cross로 판정됩니다. 이 판정은 패턴 모양이 아니라 1e-16~1e-15 수준의 반올림 오차로 정해진 것입니다. epsilon 정책을 쓰면 이런 차이를 동점으로 처리해, 오차로 판정이 갈리지 않게 합니다.

### 3. 성능 분석과 시간 복잡도 O(N²)

측정 환경: Linux, Python 3.13 (MAC 1회 평균, 필터별 10회 측정). 수치는 실행할 때마다, 컴퓨터마다 달라질 수 있습니다.

| 크기(N×N) | 평균 시간(ms) | 연산 횟수(N²) |
|---|---|---|
| 3×3 | 0.0013 | 9 |
| 5×5 | 0.0023 | 25 |
| 13×13 | 0.0136 | 169 |
| 25×25 | 0.0501 | 625 |

**연산 횟수.** MAC은 N×N개 칸마다 곱셈 1번과 덧셈 1번을 합니다. 따라서 연산 횟수는 N²이고, 시간 복잡도는 O(N²)입니다.

**측정 결과와의 연결.**
- 13×13 → 25×25: N은 약 1.9배, 연산 횟수(N²)는 625 / 169 ≈ 3.7배, 평균 시간은 0.0501 / 0.0136 ≈ 3.7배입니다.
- 5×5 → 13×13: 연산 횟수는 169 / 25 ≈ 6.8배, 평균 시간은 0.0136 / 0.0023 ≈ 5.9배입니다.
- 시간 증가율이 N의 증가율이 아니라 N²의 증가율을 따릅니다.
- 작은 크기에서 비율이 조금 낮은 이유는 함수 호출처럼 크기와 무관한 고정 시간이 함께 측정되기 때문입니다. 크기가 클수록 N²에 비례하는 부분이 대부분을 차지합니다.
